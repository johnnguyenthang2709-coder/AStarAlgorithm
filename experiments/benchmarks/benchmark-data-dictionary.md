# Final benchmark data dictionary

All CSV files use UTF-8 headers. A row is an observation, not an independent random experimental subject. Boolean CSV values are `True`/`False` for Python-generated files and `1`/`0` for the C++ road matrix. Empty means inapplicable or missing, never zero. [The final report](FINAL-BENCHMARK-REPORT.md) defines the collision conventions and experimental scope.

| File | Unit of observation | Key | Main fields and units |
| --- | --- | --- | --- |
| [Road paired input](road-astar-dijkstra.csv) | One algorithm run on one frozen directed node pair | `pair_id`, `algorithm` | `start`, `goal`: graph node IDs; `stratum`: short/medium/long; `cost_m`, `offline_cost_m`: meters; `expanded_nodes`, `generated_nodes`, `unique_discovered`, `examined_edges`, `relaxed_edges`: counts; `median_search_us`, `min_search_us`, `max_search_us`: microseconds per C++ search call. Exactly two rows per pair. |
| [Original-source eligibility audit](robot-snapshot-eligibility-audit.csv) | One frozen decision before local planner comparison | `dataset`, `snapshot_id` | `source_map`, `episode_id`, `decision_index_0based`, `source_iteration`; coordinates are source world units; `sensor_radius`: source world units; `sight_count`, `source_graph_nodes`, `source_graph_edges`, `skeleton_vertices`, `asp_vertices`: counts; `primary_reason`: mutually exclusive bundle eligibility category; `eligible_by_independent_rule`, `eligibility_checker_mismatch`: booleans. `direct_line_ground_truth_*_offline` fields are post-hoc validation only. The first two cohorts are the originally requested 118-decision/111-exclusion audit; the prospective cohort is also included. |
| [Final robot local pairs](robot-local-final-paired.csv) | One bundle-eligible frozen decision, both planners | `cohort`, `snapshot_id` | `start`, `target`: JSON pairs in source world units; `sensor_radius`: source world units; `*_planned_length`, `astar_minus_asp_length`, `source_skeleton_length`, `*_minimum_obstacle_clearance`: source world units; `*_turns`: heading changes >1e−6 rad; `*_turns_over_15deg`: changes >15°; `*_interior_collision_segments`, `*_boundary_contact_records`: segment/polygon records; `*_endpoint_error`: source world units; `*_observed_space_certified`, `*_interior_only_valid`, `*_strict_boundary_valid`, `*_radius_0_5_clearance_valid`: booleans; `*_core_median_ms`, `astar_build_median_ms`, `asp_critical_median_ms`, `asp_optimization_median_ms`: milliseconds per local component after three warm-ups and 31 measured calls; `astar_expanded_nodes`: C++ states. The `radius_0_5_clearance_valid` field is a **centerline clearance diagnostic**, not a complete disk-robot proof. |
| [Per-cohort frozen snapshots](robot-local-final-extension/robot-local-snapshots.json) | One source decision | `snapshot_id` | Current `start`, selected `target`, accumulated `sights`, source graph edges, `skeleton_path`, `asp_path`, `sensor_radius`, `source_episode_status`; all geometry in source world units. Snapshot SHA-256 is in its cohort manifest. |
| [Robot local geometry](robot-local-final-extension/robot-local-geometry-validation.csv) | One excluded state or one eligible planner path | `snapshot_id`, `method` | Same collision metrics as final pairs; `method=excluded` records selection status and does not imply planner failure. Equivalent files exist for the two earlier cohorts. |
| [Robot local timing samples](robot-local-final-extension/authors-asp-timing.json) and [A* plans](robot-local-final-extension/astar-plans.json) | One eligible snapshot with 31 measured repetitions per component | `snapshot_id` | Full per-call wall-time samples in milliseconds; Python ASP critical/optimization components and C++ binding search/build are different computational stages. Equivalent raw files exist in earlier cohorts. |
| [Legacy/radar exploration](exploration-ablation.csv) | One policy on one case/radius | `case`, `radius`, `policy` | `executed_distance`, `exploration_distance`, `retreat_distance`, `goal_distance`: world units; `astar_calls`, `expanded_nodes`, `returns`, `certified_returns`, `fallback_returns`: counts; `planning_ms`, `sensing_ms`, `selection_ms`, `wall_ms`: milliseconds; `status`, `success`: online episode outcome. Two policy rows per key. |
| [Full/cached frontier](frontier-cache.csv) | One variant on one case/radius | `case`, `radius`, `variant` | `frontier_total_ms`, `frontier_mean_ms`, `frontier_p95_ms`, `ranking_ms`, `wall_ms`: milliseconds; `equivalent_to_full`: exact paired playback/recovery equivalence flag; `eligible_snapshots`, `frontier_calls`, `score_calls`, `score_cache_hits`: counts. Two variant rows per key. |
| [Sensor radius](sensor-robustness.csv) | One online episode at radius 5 or 7 | `kind`, `case`, `radius` | `executed_distance`: world units; `turn_count`, `decisions`, `observations`, `astar_calls`, `expanded_nodes`: counts; `planning_ms`, `sensing_ms`, `selection_ms`, `wall_ms`: milliseconds; `status`, `success`: outcome. |
| [Observed-parent return trace](../../docs/bar-indoor-radar-trace.csv) | One certified return event | `frame`, `branch`, `parent` | `entry_length`, `astar_route_length`, `executed_return_length`: world units; `fallback`, `bound_verified`: booleans; `trigger`, `next_sibling`: controller state labels. |

**Pairing and aggregation.** Road pairs align by `pair_id` and directed endpoints. Robot local pairs align by the same `snapshot_id`, position, target, and frozen accumulated sights. Supporting pairs align by the composite keys above. A paired reduction or ratio is computed within each key and then summarized; it is generally different from a ratio of separately computed medians. “Median per-state median” describes robot timing across eligible states, each state already summarized from 31 calls. No full online robot path is inferred from the frozen local paths.

**Geometry convention.** Primary point validity permits obstacle-boundary contact but rejects polygon-interior entry; strict point validity rejects both. Both also require matching endpoints and complete certified coverage in the accumulated observed sights. Original full polygons are used **only** after planning. `source_robot_radius=0.5` in source snapshots is not an input to configuration-space collision checking here. Turn counts are geometric heading changes on returned polylines, not wheel commands.
